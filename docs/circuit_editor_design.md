# Reading a molecular circuit

The first question in a pocket-conditioned model is where the pocket goes and where the molecule comes out. The next question is usually about one transformation, such as which representation reaches the decoder. These tasks need different amounts of detail. The guided editor gives the first question a short path and the second a view into the selected stage.

## What made the original canvas hard to read?

The previous default, **SE(3) De Novo**, has eight blocks, thirteen wires and forty-three stored block settings. Five wires leave the same pocket output. Only one goes to the encoder. The others supply docking, auditing, export and inspection. The decoder’s `molecules` output branches to ADMET and docking. These are useful dependencies, but presenting them all beside the encoder competes with the path a reader is trying to trace. The forty-three settings are a count of the graph data, independent of how many controls appear at once. [Original preset definitions](https://github.com/daniil-777/geneuclidean/blob/1fbdc35d403266abc4707c3a178ae6a361834ab1/web/src/lib/circuitCatalog.ts)

The guided editor opens the **Tourette & Schizophrenia Champion** preset. Its ten blocks and seventeen executable wires appear as four primary stages joined by three overview links. The decoder contains two parallel connections between the guidance block and the alignment block. Molecules and reward scores travel on distinct ports, so both remain visible in its detail view. [Champion preset](../web/src/lib/circuitCatalog.ts)

## Research and design choices

| Evidence | Application to this editor |
|---|---|
| In shortest-path experiments, Ware and colleagues found that direction changes along the path and edges crossing that path affected response time after path length was taken into account. [Original study](https://doi.org/10.1057/palgrave.ivs.9500013) | Keep the principal data flow in reading order. Use visible source and destination ports. Give the two parallel decoder wires separate lanes. A reader can trace molecules and rewards through the same pair of blocks. |
| Ghoniem and colleagues compared graph representations across seven tasks. Following a path consistently favored a node-link diagram in their experiment. Looking up a link became easier with a matrix for larger, denser graphs. [Original study](https://mohammad.ghoniem.info/research/ivs-usability-2005.pdf) | Keep a visual path at the top. Open a connected diagram inside a stage and offer a textual connection list for exact endpoint lookup. The study evaluated matrices. The best choice for this particular circuit still needs testing with its users. |
| Shneiderman distinguished gaining an overview, examining a selection and relating items. TensorBoard put similar ideas into practice by grouping related operations, separating high-degree noncritical nodes and exposing a selected operation’s inputs and outputs. [Task taxonomy](https://www.cs.umd.edu/users/ben/papers/Shneiderman1996eyes.pdf) · [TensorFlow design study](https://research.google/pubs/visualizing-dataflow-graphs-of-deep-learning-models-in-tensorflow/) · [TensorBoard interaction guide](https://www.tensorflow.org/tensorboard/graphs) | Open a stage in place with a clear route back to the overview. Group real circuit instances and expose their original ports. A collapsed stage can contain several operations. Opening it should require neither panning nor finding a socket at a small zoom level. |
| Node-RED lets authors expose a chosen set of properties on a subflow while its internal nodes remain editable. A disclosure button can support both pointer and keyboard operation with an explicit expanded state. [Node-RED subflows](https://nodered.org/docs/user-guide/editor/workspace/subflows) · [W3C disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) | Show settings only after a block is selected. Start with a small set relevant to its role, such as sample count on a decoder. The separate parameter form exposes the remaining catalog settings under a disclosure and uses the same graph values and ranges. |

We considered routing every wire around the existing nodes. ELK Layered supports layered diagrams with constrained ports and orthogonal routes. This is useful when editing individual wires, but every connection would still compete for space in the opening view. We also considered expanding every stage on the same canvas. For a circuit with feedback or several shared inputs, expanding one group would make the reader follow long connections across neighboring groups. A focused stage plus a full wiring view serves both reading tasks and preserves manual layouts. [ELK layout capabilities](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)

## Connected stage diagrams and a separate form

Figma's prototype canvas attaches the connection to a specific source object and destination. Selecting the connection reveals its meaning. For a molecular circuit, that identity includes the port on each block. React Flow likewise assigns distinct identifiers to multiple handles on the same node. The Champion decoder sends both candidate molecules and scores from ensemble guidance into the alignment block. Focusing either wire should identify its endpoints and signal. This borrows the selection behavior from Figma. The circuit itself defines the sequence, signal types and port names. [Figma connection anatomy](https://help.figma.com/hc/en-us/articles/360040315773-Connect-your-prototype) · [Figma connection inspection](https://help.figma.com/hc/en-us/articles/4411431245335-View-prototype-connections) · [React Flow port identifiers](https://reactflow.dev/learn/customization/handles)

The **Diagram** view answers “what connects to what?” The **Parameter form** answers “which value should I change?” Selecting a block in the diagram exposes its common settings. The form also lets a reader select the block by name and reach its advanced settings without tracing a wire. Both views edit the same circuit instance. Textual endpoint pairs give keyboard and screen-reader users the information conveyed by the diagram. A keyboard-operable wire inspector provides the same source, destination and signal information as pointer selection. [React Flow accessibility](https://reactflow.dev/learn/advanced-use/accessibility) · [W3C guidance on complex diagrams](https://www.w3.org/WAI/tutorials/images/complex/)

The stage diagram shows dependencies that exist in the graph. The SE(3) De Novo preset has one encoder block and one decoder block. Both stages also have source-linked implementation steps for their PaiNN encoder and SAFE decoder. Those steps explain the implementation inside a block. They do not add executable circuit nodes or new output ports. Complex graphs can contain mathematically unavoidable wire crossings. Geometry checks establish behavior for the tested fixtures, while an imported circuit’s original endpoints remain available in its connection list. [Encoder and decoder annotations](../web/src/lib/circuitStages.ts) · [ELK layout capabilities](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)

## Checks on graph meaning and usability

| Task | How to check it |
|---|---|
| Trace the default generation path | Identify the pocket, encoder, decoder and candidate SMILES without zooming. SMILES represents the decoder’s molecular output. Check the source port in the graph and the generated Python. Run the browser preview and verify that its curated example strings are labeled with their provenance. The browser selects these examples from the molecule index. [Code generator](../web/src/lib/circuitEngine.ts) |
| Inspect a fork or loop | In SE(3) De Novo, locate both consumers of the decoder’s molecule output. Load the active-learning preset and trace the feedback edge. Its direction and endpoint ports must survive grouping. NanoFold and blank circuits should show only the stages their data supports. [Preset catalog](../web/src/lib/circuitCatalog.ts) |
| Edit without changing the circuit by accident | Open the form with the keyboard, change one setting, switch back to the diagram and inspect the same block in the full editor. Compare the exported nodes, edge endpoints and other settings before and after. |
| Read the layout across devices | At phone, tablet and desktop widths, inspect the generation path and the busiest stage. Measure the SVG paths in screen coordinates. Verify that both ends land on the correct port, neither parallel wire passes through a block, and the paths stay distinct at each viewport size. Use the keyboard to open a stage, select a block and return to the stage selector. |

From `web/`, run `npm run test:circuit` to check projection and routing. Run `npm run build` and `npm run test:browser -- circuit.spec.ts` to exercise the compiled editor. The browser tests measure the highlighted path at the native desktop layout, its mobile layout and a zoomed scale. They also follow the source links to the Python operation each step describes. [Browser checks](../web/tests/browser/circuit.spec.ts)

Geometry and round-trip tests can establish that controls fit and graph meaning survives. To assess whether people understand the design faster, give first-time users the tracing and editing tasks above, rotate the order of the two interfaces, and measure completion time, wrong destinations and successful edits. An automated browser run cannot supply those human measures.
